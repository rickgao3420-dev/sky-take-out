# 员工分页查询 — 全流程数据分析报告

## 一、概览

员工分页查询功能涉及从 **HTTP 请求** → **拦截器** → **Controller** → **Service** → **Mapper** → **数据库** → **逐层返回组装** 的完整调用链。本文逐层拆解每一环的数据传输、方法实现原理和底层机制。

| 层级 | 类/文件 | 核心方法/组件 |
|------|---------|-------------|
| 拦截器 | `JwtTokenAdminInterceptor` | `preHandle()` — JWT 校验 |
| Controller | `EmployeeController` | `Page()` — 接收请求，返回结果 |
| Service 接口 | `EmployeeService` | `pageQuery()` 声明 |
| Service 实现 | `EmployeeServiceImpl` | `pageQuery()` — 分页逻辑 |
| Mapper 接口 | `EmployeeMapper` | `pageQuery()` 声明 |
| Mapper XML | `EmployeeMapper.xml` | 动态 SQL |
| 分页插件 | PageHelper | 自动拦截 SQL，追加分页 |
| 消息转换 | `JacksonObjectMapper` | Java 对象 → JSON 序列化 |

## 二、请求入口 — 前端发起请求

### 2.1 HTTP 请求格式

```
GET /admin/employee/page?name=张三&page=1&pageSize=10
Authorization: token <jwt_token>
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `name` | String | 员工姓名，模糊匹配，可选 |
| `page` | int | 页码，从 1 开始 |
| `pageSize` | int | 每页记录数 |
| Header `token` | String | JWT 令牌，由登录接口颁发 |

### 2.2 参数绑定机制

Spring MVC 通过 **参数名匹配** 将 Query String 自动绑定到 `EmployeePageQueryDTO` 对象：

```
GET /admin/employee/page?name=张三&page=1&pageSize=10
          ↓ Spring MVC 自动绑定
EmployeePageQueryDTO { name="张三", page=1, pageSize=10 }
```

> **原理**：Spring MVC 的 `HandlerMethodArgumentResolver` 遍历请求参数名，通过 JavaBean 内省（`Introspector`）找到对应的 setter 方法（`setName()`、`setPage()`、`setPageSize()`）进行赋值。DTO 上的 `@Data`（Lombok）自动生成了这些 setter/getter。

## 三、拦截器层 — JWT 令牌校验

**文件**：`JwtTokenAdminInterceptor.java`

### 3.1 拦截器注册

在 `WebMvcConfiguration` 中注册：

```java
registry.addInterceptor(jwtTokenAdminInterceptor)
        .addPathPatterns("/admin/**")              // 拦截所有 /admin/ 路径
        .excludePathPatterns("/admin/employee/login"); // 排除登录接口
```

> **原理**：Spring MVC 的 `InterceptorRegistry` 将拦截器链注册到 `DispatcherServlet`。请求到达后，`DispatcherServlet.doDispatch()` 在调用 Controller 之前依次执行所有匹配拦截器的 `preHandle()` 方法。任何一个返回 `false` 都会中断链路。

### 3.2 preHandle() 方法详解

```java
public boolean preHandle(HttpServletRequest request, ...) {
    // 1. 判断是否是 Controller 方法（非静态资源）
    if (!(handler instanceof HandlerMethod)) {
        return true;  // 静态资源直接放行
    }

    // 2. 从请求头取出 token
    String token = request.getHeader(jwtProperties.getAdminTokenName());
    // adminTokenName = "token"，即从 Header 中取 "token" 字段

    // 3. 解析 JWT，提取员工 ID
    Claims claims = JwtUtil.parseJWT(adminSecretKey, token);
    Long empId = Long.valueOf(claims.get(JwtClaimsConstant.EMP_ID).toString());

    // 4. 存入 ThreadLocal
    BaseContext.setCurrentId(empId);

    return true;  // 放行
}
```

> **JWT 解析原理**：`JwtUtil.parseJWT()` 使用 jjwt 库，通过 HMAC-SHA256 算法验证签名。如果 token 被篡改、过期或秘钥不匹配，会抛出异常 → 返回 401 状态码。

### 3.3 BaseContext — ThreadLocal 机制

```java
public class BaseContext {
    public static ThreadLocal<Long> threadLocal = new ThreadLocal<>();

    public static void setCurrentId(Long id) { threadLocal.set(id); }
    public static Long getCurrentId()   { return threadLocal.get(); }
    public static void removeCurrentId(){ threadLocal.remove(); }
}
```

> **原理**：`ThreadLocal` 为每个线程维护一个独立的变量副本。Tomcat 线程池中每个请求分配一个线程，因此 `ThreadLocal` 中存储的值仅对当前请求可见，天然线程安全。员工分页查询本身不需要用户 ID，但 `BaseContext` 在新建员工等功能中用于自动填充 `create_user` / `update_user`。

## 五、Service 层 — 分页查询核心逻辑

**文件**：`EmployeeServiceImpl.java`

```java
public PageResult pageQuery(EmployeePageQueryDTO employeePageQueryDTO) {
    // 第一步：启动分页
    PageHelper.startPage(employeePageQueryDTO.getPage(),
                         employeePageQueryDTO.getPageSize());

    // 第二步：执行查询
    Page<Employee> page = employeeMapper.pageQuery(employeePageQueryDTO);

    // 第三步：提取结果
    long total = page.getTotal();
    List<Employee> records = page.getResult();
    return new PageResult(total, records);
}
```

### 5.1 PageHelper.startPage() 原理

这是整个分页查询最核心的环节。其原理如下：

```
PageHelper.startPage(pageNum, pageSize)
    ↓
1. 创建一个 Page 对象（继承 ArrayList），存储 pageNum、pageSize
    ↓
2. 将 Page 对象存入当前线程的 ThreadLocal：
   ThreadLocal<Page> LOCAL_PAGE = new ThreadLocal<>()
    ↓
3. 后续的 MyBatis 查询会被 PageHelper 的拦截器拦截
```

> **源码级原理**：PageHelper 实现了 MyBatis 的 `Interceptor` 接口。它在 `intercept()` 方法中：
> 1. 从 `ThreadLocal` 取出 `Page` 对象
> 2. 获取原始 SQL：`SELECT * FROM employee WHERE name LIKE ? ORDER BY create_time DESC`
> 3. 在执行前追加 COUNT 查询：`SELECT COUNT(0) FROM (原始SQL) tmp_count`，拿到总记录数 `total`
> 4. 根据数据库方言（MySQL）追加 LIMIT 分页：`原始SQL LIMIT offset, pageSize`
> 5. 将查询结果和 total 组装进 `Page` 对象返回

### 5.2 Page 对象

```java
public class Page<E> extends ArrayList<E> {
    private int pageNum;      // 当前页码
    private int pageSize;     // 每页数量
    private long total;       // 总记录数
    private int pages;        // 总页数
    // ... 还有 getResult(), getTotal() 等方法
}
```

> **关键设计**：`Page<E>` 继承自 `ArrayList<E>`。这意味着 MyBatis 查询返回的结果行直接被填充到这个 List 中（`list.add(row)`）——查询结果就是 Page 自身。查询完成后，PageHelper 拦截器再通过反射将 total、pages 等属性注入。

### 5.3 PageResult 封装

```java
public class PageResult {
    private long total;      // 总记录数
    private List records;    // 当前页数据
}
```

将 `Page<Employee>` 中的两个关键属性提取出来，封装成简洁的 `PageResult`，避免暴露 PageHelper 的内部类型给上层。

## 六、Mapper 层 — SQL 执行

### 6.1 Mapper 接口

**文件**：`EmployeeMapper.java`

```java
Page<Employee> pageQuery(EmployeePageQueryDTO employeePageQueryDTO);
```

> **原理**：MyBatis 通过 JDK 动态代理为 Mapper 接口生成代理对象。当调用 `employeeMapper.pageQuery(dto)` 时，代理对象根据方法名匹配到 XML 中的 `<select id="pageQuery">`，将 DTO 作为参数传入。

### 6.2 动态 SQL

**文件**：`EmployeeMapper.xml`

```xml
<select id="pageQuery" resultType="com.sky.entity.Employee">
    select * from employee
    <where>
        <if test="name != null and name != ''">
            and name like concat('%',#{name},'%')
        </if>
    </where>
    order by create_time desc
</select>
```

### 6.3 `<where>` 标签原理

```
当 name = null 时:
  SELECT * FROM employee ORDER BY create_time DESC

当 name = "张" 时:
  SELECT * FROM employee WHERE name LIKE '%张%' ORDER BY create_time DESC
```

> **原理**：MyBatis 的 `<where>` 标签智能处理条件拼接：
> 1. 如果内部至少有一个条件成立，自动插入 `WHERE` 关键字
> 2. 自动移除开头的 `AND` 或 `OR`（防止生成 `WHERE AND ...` 这类非法 SQL）
> 3. 如果内部没有条件成立，则不插入 `WHERE`

### 6.4 `concat('%',#{name},'%')` — SQL 拼接与防注入

> **原理**：`#{name}` 是 MyBatis 的**预编译占位符**（PreparedStatement），MyBatis 将其替换为 `?`，由 JDBC 驱动安全传参，**完全防止 SQL 注入**。
>
> `concat('%', ?, '%')` 在 MySQL 层面执行字符串拼接，生成 `%张三%` 作为 LIKE 模式。

### 6.5 结果映射原理

> MyBatis 配置了 `map-underscore-to-camel-case: true`（在 `application.yml` 中），自动将数据库字段的**下划线命名**映射到 Java 实体的**驼峰命名**：
>
> | 数据库字段 | Java 属性 |
> |-----------|----------|
> | `create_time` | `createTime` |
> | `update_time` | `updateTime` |
> | `id_number` | `idNumber` |
>
> **原理**：MyBatis 的 `Configuration.mapUnderscoreToCamelCase=true` 在创建 `ResultSetHandler` 时启用，对结果集中的每一列名执行下划线→驼峰转换后匹配 Java 属性。

## 七、序列化层 — 响应 JSON 的生成

**文件**：`JacksonObjectMapper.java` + `WebMvcConfiguration.java`

### 7.1 消息转换器注册

```java
// WebMvcConfiguration.extendMessageConverters()
MappingJackson2HttpMessageConverter converter = new MappingJackson2HttpMessageConverter();
converter.setObjectMapper(new JacksonObjectMapper());
converters.add(0, converter);  // 添加到列表头部，优先级最高
```

> **原理**：Spring MVC 在写入响应时，遍历 `HttpMessageConverter` 列表，找到第一个能处理当前返回类型的转换器。`MappingJackson2HttpMessageConverter` 处理 `application/json`，使用配置的 `ObjectMapper` 进行序列化。

### 7.2 JacksonObjectMapper 定制

```java
public class JacksonObjectMapper extends ObjectMapper {
    public JacksonObjectMapper() {
        // 1. 忽略未知 JSON 属性
        this.configure(FAIL_ON_UNKNOWN_PROPERTIES, false);

        // 2. 注册 Java 8 时间类型的序列化/反序列化器
        SimpleModule simpleModule = new SimpleModule()
            .addSerializer(LocalDateTime.class,
                new LocalDateTimeSerializer(DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm")))
            .addSerializer(LocalDate.class,
                new LocalDateSerializer(DateTimeFormatter.ofPattern("yyyy-MM-dd")))
            // ... 以及对应的反序列化器
        this.registerModule(simpleModule);
    }
}
```

> **关键影响**：`Employee` 实体的 `createTime` 和 `updateTime` 是 `LocalDateTime` 类型。如果不注册此模块，Jackson 默认序列化为 `[2025,7,20,14,22,0]` 数组格式；注册后序列化为 `"2025-07-20 14:22"` 字符串格式。

## 九、关键设计要点总结

### 9.1 分层架构

```
Controller → Service → Mapper → DB
   只负责      负责       负责     持久化
  请求响应    业务逻辑   SQL映射   存储
```

每一层只依赖下一层的接口，不越层调用。Controller 不知道 MyBatis 的存在，Mapper 不知道 HTTP 的存在。

### 9.2 PageHelper 的无侵入设计

PageHelper 通过 MyBatis 拦截器机制实现，对业务代码**完全透明**。开发者只需在查询前调用 `startPage()`，无需修改 SQL。

### 9.3 ThreadLocal 的使用场景

项目中 `ThreadLocal` 有两次关键使用：

| 场景 | 类 | 存储内容 |
|------|-----|---------|
| 当前用户 ID | `BaseContext` | `Long empId` |
| 分页参数 | PageHelper 内部 | `Page` 对象 |

两者都利用了 Tomcat 一个请求一个线程的特性，在线程范围内传递上下文而不污染方法签名。

### 9.4 时间格式化的一致性

`JacksonObjectMapper` 统一了 `LocalDateTime` → JSON 的序列化格式为 `yyyy-MM-dd HH:mm`。如果需要精确到秒，只需修改 `DEFAULT_DATE_TIME_FORMAT` 一处常量即可。
